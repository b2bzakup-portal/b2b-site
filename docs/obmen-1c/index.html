Как сайт и 1С будут обмениваться данными

Схема на одну страницу для общего разговора: что откуда берётся, как часто обновляется и какие решения нам нужно принять вместе, чтобы запустить обмен.

Сайт — собственная разработка, не Битрикс Только юрлица и ИП Один склад
1С — учёт

Товары, цены, остатки, клиенты, заказы и долги. Всё, что связано с деньгами и складом, живёт в 1С и правится там.

Сайт — витрина

Карточки товаров, объединение фасовок в один товар, тексты, поиск, корзина, личный кабинет и пароли клиентов.

У каждого поля один хозяин

Если цена живёт в 1С, на сайте её руками не правят, и наоборот. Две правды об одних данных — главный источник ошибок в интеграциях.

01

Схема обмена

Основа — штатный механизм 1С «Обмен с сайтами» и стандартный формат CommerceML: на нём же работают интернет-магазины на Битриксе. Инициатор всегда 1С: по расписанию она сама приходит на сайт, привозит свежие данные и забирает заказы. Сайт к базе 1С не обращается.

02

Один сеанс обмена

Так выглядит каждый сеанс по расписанию. Андрей один раз указывает в 1С адрес сайта, логин, пароль и расписание («Администрирование → Интеграция с другими программами → Обмен с сайтами»), дальше всё идёт само.

  1. 1 1С → сайт Представляется

    «Я 1С, вот логин и пароль». Сайт пускает только её.

  2. 2 1С → сайт Передаёт файлы

    import.xml — товары и группы, offers.xml — цены по типам цен и остатки, плюс картинки.

  3. 3 на сайте Сайт раскладывает

    Обновляет товары, цены и остатки у себя. Группы фасовок, собранные на сайте, не трогает.

  4. 4 сайт → 1С Забирает заказы

    «Есть новые заказы?» По каждому в 1С создаётся «Заказ клиента», клиент ищется по ИНН и КПП.

  5. 5 1С → сайт Возвращает итог

    Статус заказа, итоговый состав после менеджера и признак оплаты — клиент видит их в кабинете.

Почему так удобно

  • Штатная возможность 1С: настраивается без программирования.
  • Базу 1С не нужно открывать в интернет — сайт до неё не достаёт.
  • Если 1С на обновлении или выключена, сайт работает на последних данных.
  • Стандарт отрасли: так подключены тысячи магазинов.

Чего, по нашему опыту, нет «из коробки»

  • Уровень конкретного клиента и его оборот за год.
  • Индивидуальные цены по соглашениям — обмен передаёт цены по типам цен, а не по клиентам.
  • Мгновенность: данные свежие на момент последнего сеанса.
  • Возможно — статусы и оплата в нужном нам виде. Уточним вместе.

04

Штатный обмен или API

Штатный обмен — это тоже API поверх HTTP, просто запросы отправляет 1С, а сайт отвечает. Разница между способами — в том, кто кого спрашивает и сколько программирования нужно в 1С.

Основа

Штатный «Обмен с сайтами»

1С по расписанию отправляет XML-файлы на сайт и забирает заказы.

  • Настраивается без программирования
  • База 1С закрыта от интернета
  • Только то, что заложено в формат
Если нужно «здесь и сейчас»

Сайт спрашивает 1С

HTTP-сервис или OData в 1С: сайт сам запрашивает данные в момент показа страницы.

  • Всегда актуальные данные
  • 1С нужно публиковать в интернете и защищать
  • 1С недоступна — на сайте нет цен
  • Каждый метод пишет программист 1С
Для того, чего нет в обмене

1С сама сообщает сайту

При изменении в 1С отправляет короткое сообщение в API сайта: «у клиента сменился уровень», «заказ оплачен».

  • База 1С по-прежнему закрыта
  • Сайт не зависит от доступности 1С
  • Небольшая доработка в 1С
Предлагаем сочетание

Каталог, цены по уровням, остатки и заказы — штатным обменом. Уровень клиента, оборот, индивидуальные цены и, если понадобится, оплату — отдельным небольшим каналом. Как удобнее Андрею: сайт спрашивает 1С или 1С сама отправляет изменения?

05

Что решаем на созвоне

Пять развилок. По каждой — как задумано на сайте и что нужно услышать со стороны 1С.

5.1

Цена для конкретного клиента

Вошедший клиент видит свою цену: цену своего уровня или цену по соглашению — какая из них ниже. Клиент всегда получает лучшую доступную цену.

min ( цена уровня клиента , индивидуальная цена ) = цена для вас

Сайт считает сам Предлагаем

Из 1С приходят три типа цен, а дополнительно — уровень клиента и его индивидуальные цены. Сайт выбирает меньшую. Это уже заложено в сайт.

  • Быстро, не зависит от доступности 1С
  • Нужно дописать выгрузку уровня и индивидуальных цен

Сайт спрашивает 1С в момент показа

HTTP-сервис в 1С отвечает на вопрос «какая цена у клиента Х на товар Y». Вся логика цен остаётся в 1С.

  • Одна логика цен — в 1С
  • 1С должна быть доступна из интернета и отвечать быстро
  • 1С недоступна — на сайте нет цен

На старте — вручную в админке сайта

Из 1С приходят только три типа цен. Уровни и индивидуальные цены менеджер ставит в админке сайта, пока доработка обмена не готова. Потом переключаемся на вариант А без переделки сайта.

  • Запуск обмена не ждёт доработок
  • Временно две правды: нужна дисциплина менеджера
По умолчанию 1С берёт индивидуальную цену, даже если цена уровня ниже. Тогда цена в счёте окажется выше цены на сайте. Нужно, чтобы 1С выставляла счёт по тому же правилу «меньшая из двух» — штатно или доработкой.
5.2

Уровень клиента и «До следующего уровня»

Уровень считает 1С по оплатам за календарный год, правила и пороги живут в 1С. В кабинете клиент видит текущий уровень и строку «До следующего уровня: N ₽». Предлагаем: 1С передаёт уровень и оборот клиента, а пороги, которые меняются редко, продублированы в админке сайта — по ним сайт и считает «сколько осталось».

Считаем оборот по оплатам или по отгрузкам? Будет ли у клиентов отсрочка платежа? От этого зависит, как 1С считает уровень.
5.3

Статусы заказа и оплата

Сайт показывает клиенту шесть статусов. Нужно сопоставить их со статусами «Заказа клиента», которые отдаёт 1С. «Оплачен» в 1С означает, что по заказу нет долга, — как передавать этот признак на сайт?

5.4

Товар «Под заказ»

Статус ставится по галочке «есть у поставщика» в номенклатуре — остатков поставщиков в 1С нет. На сайте такая позиция попадает в заказ с пометкой «Под заказ, от N дней».

Что 1С делает с такой строкой: резерв, срок поставки, заказ поставщику?
5.5

Фото и описания

Фото и описания есть в 1С, забираем их при первой загрузке. Дальше карточки дополняет менеджер на сайте — и важно, чтобы следующий сеанс обмена не перезаписал его правки.

Можно ли выгрузить фото и описания один раз или только для новых позиций?

08

Словарик

Чтобы говорить на одном языке.

Комплексная автоматизация (КА)

Конфигурация 1С: склад, продажи, деньги и производство в одной базе.

Номенклатура

Справочник товаров в 1С. Каждая фасовка заведена отдельной позицией.

Характеристики номенклатуры

Способ хранить варианты одного товара внутри одной позиции. У нас не используется — фасовки объединяет сайт.

Тип цены

Именованный прайс в 1С: «Базовый опт», «Средний опт»… У каждого товара своя цена каждого типа.

Соглашение с клиентом

Документ в 1С: какой тип цены и какие скидки действуют для конкретного клиента.

Контрагент

Клиент-организация в справочнике 1С: ИНН, КПП, реквизиты.

Заказ клиента

Документ 1С, в который превращается заказ с сайта.

УПД

Документ отгрузки: счёт-фактура и накладная в одном.

CommerceML

Стандартный формат XML-файлов для обмена 1С с сайтами.

Обмен с сайтами

Штатная обработка в 1С: по расписанию отправляет каталог и забирает заказы.

import.xml · offers.xml · orders.xml

Файлы обмена: товары и группы · цены и остатки · заказы.

HTTP-сервис, OData

«Окно» в 1С, через которое сайт может запросить данные в реальном времени. Нужны веб-сервер и программист 1С.

Доработка, расширение

Изменения 1С поверх типовой конфигурации. Требуют сопровождения при обновлениях.

Полная и частичная выгрузка

Всё целиком или только изменения с прошлого сеанса.

Тестовая база

Копия рабочей базы, на которой безопасно отлаживать обмен.

ИНН и КПП

Ключи, по которым 1С узнаёт уже существующего клиента.
